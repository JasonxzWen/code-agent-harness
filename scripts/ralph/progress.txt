## Codebase Patterns

- v0.1 blockers are tracked in `docs/checklists/v0.1-readiness-gap-list.md`; release-wide status is mirrored in `docs/checklists/release-checklist.md`.
- Required implementation quality gate is `bun run quality`, which runs format check, lint, typecheck, tests, and smoke.
- Keep v0.1 scope read-only: do not add file editing, patch application, persistent memory, product subagents, MCP, sandbox runtime, dashboard, IDE extension, or background task mode.
- Trace redaction evidence should exercise `createJsonlEventLogger` so tests cover serialized JSONL output, not only helper functions.
- Tool output truncation evidence should assert machine-readable limit and size/count fields, not only `truncated: true`.
- Run cancellation belongs in core through `AbortSignal`; the CLI may create and abort the controller, but provider/tool execution must remain in core/tools.
- v0.3 release work stays local and deterministic: fixed eval tasks, JSONL trace scoring, JSON/Markdown/HTML reports, report privacy, and release evidence. Do not add leaderboard, hosted service, LLM judge, context engineering, memory, delegation, sandbox, or MCP.
- v0.3 eval is a separate release-readiness gate: run `bun run eval -- --suite v0.3 --out .agent-harness/evals/latest` and record actual results; `bun run quality` remains format/lint/typecheck/build/test/smoke.
- `docs/research/v0.3/evaluation-harness-technical-report.html` is a technical research artifact, not the eval runner generated `.agent-harness/evals/<run>/report.html`.
