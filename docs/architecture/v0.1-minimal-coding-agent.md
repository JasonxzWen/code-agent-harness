# v0.1 Minimal Coding Agent Architecture

## Problem

The project needs a minimal but real coding agent harness that can run inside a repository, inspect files through tools, and generate grounded answers.

## Design summary

```txt
User Task
→ TUI
→ Agent Controller
→ Provider Client
→ Tool Call
→ Tool Registry
→ Permission Gate
→ Tool Executor
→ Tool Result
→ Provider Client
→ Final Answer
→ JSONL Trace
```

## Components

```txt
apps/cli
  └─ Ink TUI
      ├─ TaskInput
      ├─ EventStream

      └─ FinalAnswer

packages/core
  ├─ AgentController
  ├─ AgentLoop
  ├─ AgentState
  ├─ ConfigLoader
  ├─ PromptBuilder
  ├─ PermissionGate
  └─ EventLogger

packages/tools
  ├─ ToolRegistry
  ├─ list_files
  ├─ read_file
  ├─ search_repo

packages/providers
  ├─ ProviderClient interface
  ├─ OpenAI adapter
  ├─ Anthropic stub
  └─ Mock provider
```

## Core loop

```ts
while (run.status === "running" && step < maxSteps) {
  const messages = buildMessages(runState);
  const response = await provider.generate({ messages, tools });

  if (response.type === "tool_call") {
    for (const call of response.calls) {
      const preflight = await toolRegistry.prepare(call, repoContext);
      if (!preflight.ok) {
        appendToolResult(runState, preflight.result);
        continue;
      }

      const decision = await resolvePermission(preflight.prepared);
      const result =
        decision === "allow"
          ? await toolRegistry.execute(call, { ...repoContext, permission: decision })
          : permissionDeniedResult(preflight.prepared);
      appendToolResult(runState, result);
      eventLogger.write(...);
    }
    continue;
  }

  if (response.type === "final") {
    runState.finalAnswer = response.content;
    break;
  }
}
```

## Trade-offs

| Decision                    | Alternative         | Reason                                           |
| --------------------------- | ------------------- | ------------------------------------------------ |
| Read-only v0.1              | edit-capable v0.1   | proves runtime safely before writes              |
| JSONL trace                 | SQLite / OTEL       | simpler, inspectable, eval-ready                 |
| OpenAI first                | full multi-provider | validates boundary without doubling adapter work |
| Internal tool protocol      | MCP first           | keeps core runtime focused                       |
| Tool-driven repo inspection | preload whole repo  | safer for context budget and grounding           |

## Boundaries

```txt
apps/cli must not execute tools directly.
packages/core must not import concrete provider SDK types.
packages/providers must not import Ink.
packages/tools must not depend on providers.
Command execution must exist only inside run_command.
Filesystem reads must pass path and secret policy.
```
