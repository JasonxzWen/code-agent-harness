# v0.1.0 Minimal Coding Agent

## Summary

`v0.1.0` delivers a runnable, terminal-first, read-only coding agent harness for
real repositories. The harness can accept a user task, call validated repository
inspection tools, return a grounded final answer, and write a JSONL trace.

## Scope

- Ink-based terminal UI for task entry, progress display, permission prompts,
  final answers, and run abort.
- Core agent loop with provider-neutral messages, tool calls, permission checks,
  run state, and trace events.
- Safe read-only tools for file listing, file reading, repository search, git
  status, and restricted read-only command execution.
- Strict Zod validation for model-generated tool input.
- OpenAI provider adapter and mock provider for deterministic smoke tests.
- JSONL event logging with redaction for secret-like keys and API-key-like
  values.
- Explicit truncation metadata for bounded tool and command outputs.
- Local CLI bundle build through `bun run build`.
- Ralph workflow files used to close the final v0.1 readiness blockers.

## Non-goals

This release intentionally does not include:

- file editing;
- patch application;
- persistent memory;
- product-level subagents;
- MCP integration;
- sandbox runtime;
- eval dashboard;
- background task mode;
- IDE extension.

## Demo

```bash
bun install
bun run build
bun dist/agent-harness.js --repo fixtures/tiny-ts-repo --task "Explain this repository structure and identify the main modules."
```

The development entrypoint remains available:

```bash
bun run dev -- --repo fixtures/tiny-ts-repo --task "Explain this repository structure and identify the main modules."
```

During an active TUI run, press `q` or `Ctrl+C` to abort.

## Architecture

```txt
User Task
-> TUI
-> Agent Loop
-> Provider Client
-> Tool Registry
-> Safe Tool Execution
-> Provider Client
-> Grounded Final Response
-> JSONL Trace
```

Package boundaries remain:

- `apps/cli`: TUI and user interaction.
- `packages/core`: agent loop, state, permission, config, and event contracts.
- `packages/tools`: read-only tools, validation, and safety policy.
- `packages/providers`: provider adapters and normalized provider boundary.

## Known Limitations

- v0.1 is read-only and cannot edit or patch files.
- `run_command` is intentionally restricted to a small read-only allowlist.
- The build emits a local Bun CLI bundle and externalizes runtime dependencies;
  use it after `bun install`.
- OpenAI is the first real provider. Multi-provider behavior beyond the current
  boundary remains future work.
- OpenAI provider tool results are not yet mapped through provider-native
  `tool_call_id` messages. See `docs/agent/openai-provider.md`.
- Live provider smoke requires `OPENAI_API_KEY`.
