# v0.2.1 Chinese-first Repository Migration Contract

## Alignment brief（对齐简报）

### What（内容）

`v0.2.1` 迁移的是仓库的语言契约和可读性契约，不改变产品运行时能力。目标是让 release docs、research、spec、ADR、engineering standards、checklists、agent docs、templates、skills、README、CHANGELOG 和 `AGENTS.md` 进入“中文优先”的长期维护状态，并让核心源码通过中文注释解释 what、why、how。

代码标识符、命令、路径、包名、API 名称、外部项目名和引用标题保留原文。用户可读正文、Mermaid 节点、表格字段、验收说明和 reviewer handoff 默认使用中文。

### Why（原因）

仓库已经从 `v0.2.0` 开始要求新增 release-facing 文档使用中文，但规则分散在少数工程文档里。`v0.2.1` 需要把语言政策变成可执行的 release scope：后续会话读取 `AGENTS.md` 和 engineering docs 后，应能明确知道默认中文迭代、中文规范、中文验收和中文汇报。

### How（方案）

迁移分五步推进：

1. 先建立语言政策、模板规则、release contract、research、spec 和 checklist。
2. 再迁移 release-facing docs，包括 release note、contract、readiness checklist 和顶级报告。
3. 再迁移 engineering docs，保证生命周期、测试、验收、benchmark 和 review handoff 规则一致。
4. 再迁移 agent/tool docs 和 skills，使未来 agent session 默认中文协作。
5. 最后处理历史 ADR、research、spec 和旧 release 文档；历史文档可按风险分批保留、补摘要或翻译。

### 行业实践

调研信号来自 Codex、Claude Code、opencode、Aider、OpenHands、AGENTS.md 标准、GitHub Docs 和 Read the Docs。主流 coding agent 项目普遍把仓库指令放在 Markdown 文件里，并强调指令要短、结构化、可继承、可验证。通用文档平台则倾向于明确主语言、独立管理本地化流程，避免多个语言版本无边界漂移。

本项目因此选择“单仓中文正文为权威源”，暂不建立中英双轨全文翻译系统。

### 验收

`v0.2.1` 完成时必须满足：

- 新增语言政策明确中文正文、英文保留项和暂缓项。
- `AGENTS.md` 与 engineering docs 明确后续默认中文迭代。
- readiness checklist 覆盖迁移前、中、后的 blockers、证据和验收项。
- research/spec/release contract 能指导下一次中文 release，而不是只描述愿望。
- 核心源码文件使用 UTF-8 编码；核心逻辑有适当中文注释，能帮助新手理解主要运行路径。
- 未运行的 E2E、benchmark 或质量门禁必须标为未运行，不得写成通过。

### E2E

新会话只读取 `AGENTS.md`、`docs/engineering/language-policy.md`、`docs/engineering/standards.md` 和 `docs/engineering/release-documentation-standard.md` 后，应能回答：

- 后续仓库文档和汇报默认使用中文；
- 哪些英文技术标识必须保留；
- 不得批量翻译代码符号、命令块、路径和外部引用标题；
- 下一次 release 的 contract、research、spec、checklist 和 final report 应如何验收。

### Benchmark

先定义人工 audit benchmark，不在本阶段实现自动扫描脚本：

| Benchmark question               | Metric                 | Method                                         | Threshold for v0.2.1     |
| -------------------------------- | ---------------------- | ---------------------------------------------- | ------------------------ |
| 仓库是否已建立中文优先入口规则？ | 入口文档覆盖率         | 人工检查 `AGENTS.md`、engineering docs、skills | 关键入口 100% 有规则引用 |
| 新增 v0.2.1 文档是否中文正文？   | 新增文档中文正文比例   | 人工抽查正文段落                               | 新增规划文档 100%        |
| 剩余英文正文是否可追踪？         | 剩余英文正文清单完整度 | 按文档分类建立 gap list                        | 所有主要类别有 audit 项  |
| 技术标识是否被误翻译？           | 保护项误翻译数         | 抽查命令、路径、API、包名、代码标识符          | 0 个已知误翻译           |
| 核心逻辑是否可读？               | 中文注释覆盖率         | 人工抽查核心源码路径的 what/why/how 注释       | 核心路径 100% 有解释     |
| 语言扫描是否可重复？             | 启发式扫描 blocker 数  | 运行 `bun run audit:language`                  | 0 blocker                |

第一版语言扫描作为独立 release readiness gate 运行，不接入 `bun run quality` 或 CI。待 allowlist 和误报率稳定后，再升级为 blocking quality/CI gate。

### 风险

- 误翻译代码符号导致文档无法对应真实代码。规避：保护代码标识符、命令、路径和 API 名称。
- 批量翻译破坏 Markdown 表格、Mermaid 和命令块。规避：先制定规则和 checklist，再分批迁移。
- 把未运行的 benchmark 写成已通过。规避：所有 evidence 必须区分 `planned`、`manual audit` 和 `run`。
- 历史文档翻译造成语义漂移。规避：历史 ADR/research/spec 放到后续阶段，先做索引和 gap list。

## Scope classification 分类

`later release`，作为 `v0.2.0 Patch-capable Agent` 之后的 process/docs release。它不改变 agent loop、provider、tool registry、patch tool、MCP、sandbox、subagents、IDE extension 或 UI 行为。

## 目标

- 定义中文优先仓库语言政策。
- 建立迁移清单、分类、顺序、风险控制和验收机制。
- 产出 `v0.2.1` research、spec、readiness gap list。
- 更新必要入口，让未来会话默认中文协作。
- 定义手工 benchmark 和后续自动化扫描计划。
- 完成第一批低风险迁移：模板、README、CHANGELOG、AGENTS.md 和仓库 skills。
- 完成全仓 Markdown 文档迁移：release、research、spec、ADR、checklist、engineering、agent、architecture 和 auxiliary docs。
- 为核心源码补充中文注释，确保 agent loop、tool registry、permission/safety policy、provider adapter、trace redaction、CLI permission flow 和 smoke path 的 what/why/how 可读。
- 新增 `bun run audit:language`，用于重复扫描明显英文正文残留和核心源码中文注释覆盖缺口。

## 非目标

- 不改变产品运行时行为、API、权限模型或功能范围。
- 不重写业务逻辑；只允许文档迁移和注释级源码可读性改动。
- 不改动 `apply_patch`、provider、CLI/TUI、sandbox、MCP 或 subagent scope。
- 不建立多语言站点、机器翻译流水线或 release 发布自动化。
- 不声称未执行的自动扫描、E2E 或 benchmark 已通过。
- 不迁移代码标识符、命令、路径、包名、API 名称、外部项目名和引用标题。

## 验收标准

- `AGENTS.md` 明确始终中文回复，以及 `v0.2.1` 后仓库正文文档中文优先。
- `docs/engineering/language-policy.md` 定义必须中文、允许英文、暂缓迁移和禁止误翻译的内容。
- `docs/engineering/standards.md` 和 `docs/engineering/release-documentation-standard.md` 链接语言政策。
- 三个仓库 skills 明确其输出和新增文档遵守中文优先政策。
- `docs/checklists/v0.2.1-readiness-gap-list.md` 按 release docs、research/spec/ADR、engineering standards、checklists、agent docs、templates、skills、README/CHANGELOG/AGENTS 分类列出 audit 项。
- 第一批迁移覆盖模板、README、CHANGELOG、AGENTS.md 和仓库 skills；后续全量迁移覆盖所有 repository Markdown docs；没有产品功能代码变更。
- 核心源码注释使用中文和 UTF-8，解释 what、why、how；注释改动不得改变 runtime behavior。
- `bun run audit:language` 通过，且脚本仍作为独立 readiness gate，不进入 `bun run quality` 或 CI。

## 质量门禁

完成本阶段后运行并报告：

| Command                  | Required | Notes                                      |
| ------------------------ | -------- | ------------------------------------------ |
| `bun run format:check`   | yes      | Markdown 格式必须通过现有格式规则。        |
| `bun run lint`           | yes      | 不应受纯文档改动影响。                     |
| `bun run typecheck`      | yes      | 不应受纯文档改动影响。                     |
| `bun run build`          | yes      | 确认未破坏 workspace 构建。                |
| `bun run test`           | yes      | 确认文档/规范更新未引入测试漂移。          |
| `bun run smoke`          | yes      | 确认 CLI smoke 仍可执行。                  |
| `bun run quality`        | yes      | 汇总质量门禁。                             |
| `bun run audit:language` | yes      | 独立语言审计；v0.2.1 暂不接入 quality/CI。 |
